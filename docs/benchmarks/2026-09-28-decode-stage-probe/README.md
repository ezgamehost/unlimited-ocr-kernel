# Temporary decoder stage attribution

This test-only probe surrounds unchanged decoder stages with wall clocks. It is diagnostic instrumentation, not a proposed runtime optimization. The instrumented and preserved accepted executables ran in ABBA order on AC with eight workers, 1,517 prefix tokens, 512 teacher-forced steps, one warmup and three measured repetitions per process. All 16 full-logit hashes match. Every repetition asserts exactly 6,144 calls for each per-layer stage and 512 output-head calls; enclosing stage durations are less than total decode including checksums.

`stage-summary.json` reports medians from the six measured instrumented samples. The enclosing MLP/expert stage is about 36% of total, attention/RoPE/cache about 22%, input normalization/QKV about 19%, vocabulary head about 13%, and output projection/post-normalization about 7%. These are wall-clock stage fractions, not the earlier aggregate thread sample counts. Stages include synchronization and allocations inside their boundaries. Remaining time includes embedding, wrapper and checksum work. Timer and atomic-counter overhead exists; no stage attribution is a proof of optimization benefit.

The uninstrumented median is 3.855277917 seconds and instrumented median 3.805750166 seconds, with overlapping ranges and host/code-layout variation. No speedup is claimed from instrumentation. All raw timings and identities are retained. The patch is saved under `powered-abba-1/candidate.diff`; the temporary source changes have been reverted. The accepted CLI remains `1846f3dd7495e3fb0e675ce38931de1daae4bda967f6ad13bba65e885a2e93b3`.

The next bounded hypothesis is concurrent Q/K/V projections for a single token: their outputs are independent, while the current runtime schedules three separate row-parallel projections. An experiment can use three serial inner projections in the existing pool, preserve every row arithmetic order, reserve aggregate scratch conservatively and retain the original low-memory/multi-token paths.
